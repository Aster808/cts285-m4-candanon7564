Optional credit · fall break

Fall Break Adventure

Build a choose-your-own-adventure story that a real person plays.

Branches. Loops. Functions. And one new step: you plan before you code.

Use the arrow keys, the space bar, or swipe.

The new step

Plan first. Then code.

PLAN→GATE→BUILD

The planning gate: your player reads your plan and says yes, I would play that.

No yes, no code. Planning and building are two different jobs.

Real teams work this way. A plan that is wrong costs minutes to fix. Code that is wrong costs hours.

Step 1 · requirements

Who is it for?

Pick one real player. A classmate, a friend, a family member. Interview them. Write down what they say.

  1. What kind of stories do you like?
  2. How many minutes do you want to play?
  3. What do you not like in a story game?
  4. How do you want it to end?
  5. Where will you play?

Do not argue. Do not fix. Write.

Step 2 · user stories

One sentence per need

As a [kind of player],
I want [an action],
so that [a reason].
GOOD

As a player with 5 minutes, I want 3 or 4 choices before an ending, so that I finish before class.

WEAK

As a player, I want a cool game.

No action. No reason. Nobody can test it.

Write 4 or 5. Each one must come from something your player said.

Step 3 · acceptance checks

A yes/no test for each story

A check names something you can see or count.

WEAK

The game is fun.

STRONG

I can reach an ending in 4 choices or fewer.

When the code is done, play your story and tick each check yourself. A story that fails a check is not done.

Step 4 · story map

Boxes and arrows

            [passage_start]
              /         \
             v           v
     [passage_door] [passage_closet]
            |            |
            v            v
    [ending_caught] [passage_hallway]
                      /        \
                     v          v
           [ending_free] [ending_caught]

A box is a passage. An arrow is a choice. This map leaves out the "go back" arrows.

Core size: 8 passages, 2 endings. Open widget.html to explore a full map.

Step 5 · build

A passage is a function

Python

def passage_door():
    print("The front door is locked.")
    choice = ask("What do you do?", [
        "Shake the handle hard",
        "Go back",
    ])
    if choice == 1:
        ending_caught()
    elif choice == 2:
        passage_start()

C++

void passage_door() {
    cout << "The front door is locked.\n";
    int choice = ask("What do you do?", {
        "Shake the handle hard",
        "Go back",
    });
    if (choice == 1) {
        ending_caught();
    } else if (choice == 2) {
        passage_start();
    }
}

Names start with passage_ or ending_. The checker reads these names.

Branches

A choice is an if

ask() shows the options and returns a number. Your if and elif pick the next passage.

In the codeOn the map
One option in ask()One arrow out of the box
One if or elifWhere that arrow points
A call to ending_free()An arrow into an ending

Add an option and you add an arrow. Forget the elif and the arrow goes nowhere.

Loops

Two loops in your story

Loop 1: retry (provided)

while True:
    ...
    if raw.isdigit() and 1 <= int(raw) <= len(options):
        return int(raw)
    print("Enter a number from 1 to 2.")

It repeats until the input is valid.

Loop 2: replay (you write it)

playing = True
while playing:
    passage_start()
    again = ask("Play again?", ["Yes", "No"])
    if again == 2:
        playing = False

Step 6 · check

Let the checker read your map

python story_check.py adventure_start.py --map

FINDINGS (1)
  ORPHAN      passage_vent cannot be reached from passage_start.
              Fix: Add a choice in another passage that leads here.
  • ORPHAN: no way to reach it
  • DEAD END: no way out
  • BROKEN LINK: goes nowhere
  • TRAP: no way to an ending
  • NO START, NO ENDING
  • --map prints a Mermaid map

It works on Python, C++, and Twee files.

Coda · optional AI helper

Prompt in stages

One big prompt gives an answer you cannot check. Split the work. Each stage feeds the next.

1 Idea

"Ask me 5 questions, one at a time, to help me find an idea. Wait for each answer."

2 Plan

"Write 4 user stories from my notes. Use only things in my notes."

3 Build

"Write passage_x in the same style as this one. Return only the function."

Every prompt: who is it for, how big, what shape, what happens next. One task per prompt. You check the answer.

Full prompts are in coda-prompts.md. Keep a log in prompts.md.
